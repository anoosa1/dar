Mail — three directions and shared screens

Mail is a built-in optional app at /mail inside the selected frame (unified look B, Twilight Afterglow/Nightfall). It connects several accounts at once over JMAP or IMAP + SMTP, with Google and Microsoft signing in through OAuth2 (XOAUTH2). Every message is mirrored in full: the original .eml lives in the Files folder docs/mail, and headers, flags and text sit in account-scoped module tables for fast lists, search and live updates. The three directions share the features below and differ only in how you read and reply. The shared screens (S1–S4) apply to whichever direction you pick.

  • Accounts: several at once, each with its own color; a unified inbox or one account at a time. Identities (send-as addresses) and signatures per account.
  • Protocols: JMAP (Fastmail, Stalwart, any RFC 8620/8621 server), IMAP4rev1/rev2 with IDLE, CONDSTORE/QRESYNC when offered, and SMTP submission (465 TLS or 587 STARTTLS).
  • Sign-in: password or app password, JMAP API token, or OAuth2 for Google and Microsoft. Secrets are encrypted at rest with the runtime's KeyBox and are never logged.
  • Mirror: each message's original .eml is written to docs/mail/<account>/<folder>/ in Files, so it is versioned, backed up and searchable like any file. Deleting on the server moves the copy to deleted files.
  • Reading: threads (JMAP threads, IMAP THREAD or References), sanitized HTML with remote images blocked until allowed, attachments saved to Files or previewed.
  • Writing: compose, reply, reply all and forward; contact autocomplete from Contacts; attachments from Files or upload; drafts saved on the server; undo send for 10 seconds.
  • Organizing: read/unread, flag, archive, move, delete, spam; folders (IMAP) or mailboxes (JMAP); keyword labels; multi-select with the tonal bar.
  • Everywhere: subjects and senders in the shared search, an unread badge on the rail, keys (c compose, r/a/f, e archive, # delete, j/k), phones and both themes.
  • Safety: no offline editing or end-to-end encryption; servers are reached through TLS only (no plain IMAP/SMTP); private addresses are refused unless the operator allows them; one sync worker per account, owned by the runtime and stopped deterministically.

CancelSign in and add
  • Google and Microsoft use OAuth2 with PKCE; Dar stores the refresh token (KeyBox) and signs IMAP/SMTP in with XOAUTH2. The operator registers the client IDs in the NixOS module; without them these tiles say “Not set up on this server”.
  • JMAP wins when the domain offers it; IMAP+SMTP is the fallback and can be forced in manual setup.
  • Manual setup asks for IMAP host/port, SMTP host/port and the user name; only TLS or STARTTLS are offered.
  • Sign in and add tests the login first; a failure keeps the form and names the step (connect, TLS, login).
  • Private addresses (a home server on the LAN) are refused unless the operator allows them, as News does.
