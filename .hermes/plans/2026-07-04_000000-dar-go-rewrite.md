# Dar Go Rewrite — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Rewrite Dar from scratch in Go as a full Nextcloud replacement (Files, Contacts, Calendar, Todo, Notes, News, Email, Photos) with Soosa AI deeply integrated into every app.

**Architecture:** Main HTTP server + daemon-per-app (process isolation). Soosa is the central AI daemon — every app registers its capabilities as tools with Soosa, so the AI can search files, create events, manage contacts, summarize email, etc. Server-rendered HTML with Tailwind CDN and vanilla JavaScript. OIDC auth with session cookies. SQLite via pure-Go driver (no CGo).

**Tech Stack:**
- **Language:** Go 1.24+
- **SQLite:** `modernc.org/sqlite` (via `zombiezen.com/go-sqlite`, pure Go, no CGo)
- **Router:** `github.com/go-chi/chi/v5`
- **OAuth2/OIDC:** `golang.org/x/oauth2`
- **Templates:** `html/template` (stdlib, auto-escaping)
- **IMAP:** `github.com/emersion/go-imap`
- **iCal/vCard:** `github.com/emersion/go-ical`, `github.com/emersion/go-vcard`
- **RSS:** `github.com/mmcdole/gofeed`
- **Frontend:** Tailwind CSS CDN, vanilla JS, Material 3 design tokens
- **Images:** `image/*` stdlib for thumbnail generation

**Total Go dependencies: 7** (chi, oauth2, sqlite, go-imap, go-ical, go-vcard, gofeed)

**Implementation:**

```go
package db

import (
    "context"
    "fmt"
    "zombiezen.com/go/sqlite"
    "zombiezen.com/go/sqlite/sqlitemigration"
)

type DB struct {
    pool *sqlitemigration.Pool
}

// Open opens a SQLite database at the given path and runs migrations.
func Open(ctx context.Context, path string, migrations []string) (*DB, error) {
    schema := sqlitemigration.Schema{
        Migrations: migrations,
    }
    pool, err := sqlitemigration.Open(ctx, path, schema)
    if err != nil {
        return nil, fmt.Errorf("open db: %w", err)
    }
    // Enable WAL mode
    conn, err := pool.Take(ctx)
    if err != nil {
        pool.Close()
        return nil, fmt.Errorf("take conn: %w", err)
    }
    defer pool.Put(conn)
    if err := sqlite.Execute(conn, "PRAGMA journal_mode=WAL;", nil); err != nil {
        pool.Close()
        return nil, fmt.Errorf("wal mode: %w", err)
    }
    return &DB{pool: pool}, nil
}

// Conn gets a connection from the pool.
func (db *DB) Conn(ctx context.Context) (*sqlite.Conn, func(), error) {
    conn, err := db.pool.Take(ctx)
    if err != nil {
        return nil, nil, err
    }
    return conn, func() { db.pool.Put(conn) }, nil
}

// Close closes the database.
func (db *DB) Close() error {
    return db.pool.Close()
}
```

package server

import (
    "context"
    "net/http"
    "github.com/anoosa/dar/internal/auth"
    "github.com/anoosa/dar/internal/db"
    "github.com/go-chi/chi/v5"
    "github.com/go-chi/chi/v5/middleware"
)

type Server struct {
    DB       *db.DB
    OIDC     *auth.OIDCProvider
    Router   chi.Router
    HTTP     *http.Server
}

type contextKey string
const UserContextKey contextKey = "user"

func New(db *db.DB, oidc *auth.OIDCProvider) *Server {
    s := &Server{DB: db, OIDC: oidc}
    r := chi.NewRouter()
    r.Use(middleware.Logger)
    r.Use(middleware.Recoverer)
    r.Use(s.sessionMiddleware)
    s.Router = r
    s.HTTP = &http.Server{Handler: r}
    return s
}

func (s *Server) Start(addr string) error {
    s.HTTP.Addr = addr
    return s.HTTP.ListenAndServe()
}

import (
    "html/template"

type Registry struct {
    apps []App

func NewRegistry() *Registry { return &Registry{} }

func (r *Registry) Register(app App) {
    // Insert sorted by AppBarOrder
    idx := sort.Search(len(r.apps), func(i int) bool {
        return r.apps[i].AppBarOrder() >= app.AppBarOrder()

    r.apps = append(r.apps, nil)
    copy(r.apps[idx+1:], r.apps[idx:])
    r.apps[idx] = app

## Open Questions

1. **Git repo:** Dar isn't in a git repo yet. Init one with the existing Zig code on `master`, then branch `go-rewrite`? Or start a fresh repo?

2. **Soosa LLM backend:** Which LLM provider? OpenAI-compatible API assumed. Should Soosa support multiple providers (OpenAI, Anthropic, local llama.cpp)? This affects the LLM client implementation.

3. **Email password storage:** How to store IMAP/SMTP passwords? Encrypted at rest with a master key? Or rely on filesystem permissions?

4. **Photo EXIF library:** The Go stdlib doesn't parse EXIF. Add `github.com/rwcarlsen/goexif` (8th dependency)? Or write a minimal EXIF parser?

5. **Share links:** Public share links need to be accessible without auth. How to handle this — a separate endpoint that loads share metadata from DB and serves the file? Or a separate lightweight HTTP handler?

6. **Daemon management on production:** The current plan has `cmd/server` spawning daemons as child processes. For production, should daemons be managed by systemd/supervisor instead? If so, the daemon manager becomes optional.

7. **Database per daemon vs shared?** Currently one SQLite DB. Should each app daemon have its own SQLite DB for isolation? Or shared with WAL mode? Shared is simpler for Soosa cross-app queries.

8. **Testing OIDC:** How to test OIDC flow? Mock OIDC server or use a test provider?

9. **Go version:** Which minimum Go version? 1.22+ for `net/http` routing enhancements, or 1.21 for broader compatibility?

10. **Photo face recognition:** Mentioned as a stretch goal. Out of scope for initial implementation? Or should the architecture leave room for it?
